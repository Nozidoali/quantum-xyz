## Key design decisions made during execution

**Real-amplitudes-only QState.** `QState` drops imaginary parts on
construction. The qiskit reference in `test_gate_apply.py` projects via
`np.real(...)` AND — after Task 5 — normalizes the result so it matches
xyz's always-normalized `to_vector()`. Under this convention:

- `RX.apply` and `RZ.apply` collapse to scalar multiplication by
  `cos(θ/2)` (the complex parts vanish when projected to real; the
  amplitude factor survives).
- `U.apply` is matrix multiplication with `np.real(U)` restricted to the
  two-amplitude subspace indexed by the target bit.
- `CRX` / `CRZ` / `CU` apply the same transforms conditionally on
  `is_enabled(idx)`, identity otherwise.
- `MCMY` and `MULTIPLEXY` are RY-like (real math all the way) — they
  look structurally identical to the existing `MCRY.apply`.

**Trait storage convention.** `ControlledTrait` and
`MultiControlledTrait` both expose `self.control_qubits` as a list. For
singly-controlled gates the list has exactly one element. External
callers universally use `gate.control_qubits[0]` for the singular case.
MULTIPLEXY is an outlier (extends `AdvancedGate` not `ControlledTrait`)
and keeps its own `control_qubit` instance attribute — Task 3 also added
`self.control_qubits = [control_qubit]` so the list interface is still
available.
