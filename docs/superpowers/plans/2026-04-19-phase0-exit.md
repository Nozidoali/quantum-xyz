## What changed vs. the original plan

- Case matrix narrowed from 45 → 30. Random dense n≥5, sparse k=8, and dicke
  (n,k) with k≥2 at n≥5 were dropped. Rationale: these blow past the
  regression time budget on the available compute. The dropped categories
  remain accessible via `generate_bounds.py` if they are ever re-enabled.
- Legacy `tests/test_algorithms/test_dicke.py` narrowed to the same 5 pairs
  that survive in the regression dicke suite.
- `tests/test_algorithms/test_prepare_state.py::test_qsp_1` is gated behind
  `@pytest.mark.slow` — uncovered, it took >1h on its own. The `slow`
  marker is registered in `pyproject.toml`.
- The generator script invocation is `python -m tests.regression.generate_bounds`
  (run from the repo root, with Python 3.10+ via the poetry venv). PEP 420
  namespace packages make this work without a `tests/__init__.py`.
- `generate_bounds.py` uses a fresh `np.random.default_rng(SEED)` per case
  group, mirroring the per-file test fixtures. Earlier versions threaded a
  single rng through all groups, which caused sparse bounds to drift from
  the vectors the sparse test fixture produced.
- `pyproject.toml` had two duplicate TOML issues (`[build-system]` listed
  twice, `authors` key duplicated) that modern parsers rejected. Fixed
  minimally — poetry-core build-system preserved.

## Time budget note

The original spec called for a <2min regression suite. In practice the
library's current state takes ~7 min for the kept matrix, dominated by
three `dense_random_n4` cases at ~135 s each. We accepted the longer
runtime rather than further narrow coverage. The suite is not a per-commit
CI gate; it is the pre-merge check for each refactor phase.

Run on slurm (`srun -p debug -A jcgroup --qos=low ...`) — the headnode is
too slow for `xyz.prepare_state`.
