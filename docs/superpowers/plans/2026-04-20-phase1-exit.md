## Unexpected win from Bug 2's fix

Runtime dropped from 6:49 (Phase 0) to 2.76s — a 150× speedup. The
cause: Bug 2's fix silently enabled the correct flow for dense states.

Pre-fix, every call to `_prepare_state_rec` discarded the caller's
`param` and re-built a default `StatePreparationParameters` instance
(which had `enable_m_flow=True, enable_n_flow=False`). `prepare_state`'s
outer heuristic picked `enable_n_flow=True, enable_m_flow=False` for
dense targets, but the inner function ignored that choice. So dense
states ran the cardinality-reduction (m-flow) pipeline — slow, and
designed for sparse states — instead of the qubit-reduction (n-flow)
pipeline.

Post-fix, dense states correctly take the n-flow path. `dense_random_n4`
cases drop from ~135s each to ~0.07s each.

The existing golden bounds (generated pre-fix) are still valid upper
bounds: post-fix CNOT counts are lower than pre-fix for every dense
case, so all `actual <= bound` assertions hold. No bounds regeneration
is needed for Phase 1 to pass, though a future phase that wants a
tighter bound may choose to re-run `python -m tests.regression.generate_bounds`.

## Things to be aware of for Phase 2

- `_prepare_state_rec` no longer accepts `**kwargs`. Any future caller
  must pass `stats=`, `param=`, `verbose_level=` by name.
- `Z.apply` now has a real implementation. Phase 2's `test_gate_apply`
  parametrization already includes `Z` in the xfail set — once Phase 2
  removes `Z` from `UNIMPLEMENTED_APPLY` and wires `_apply_on_qiskit`,
  the test promotes from xfail to passing automatically. The `Z.apply`
  implementation landed in Phase 1 already, so the xfail is an
  artifact of the strict ABC contract Phase 2 introduces; the gate
  itself already works.
